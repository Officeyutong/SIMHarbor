# Experimental native installation bridge

**English** | [简体中文](NATIVE_INSTALL.zh-CN.md)

The bridge intercepts Core Telephony methods inside an injected app. It answers the eSIM support queries and forwards `addPlanWith:completionHandler:` requests to SIMHarbor; it is not a system registration of a third-party LPA. The jailbreak must permit injection into the calling app. Apps that use different capability or installation interfaces may not use this bridge.

The calling process opens SIMHarbor and sends the request over a separate authenticated loopback connection. If network access has not been authorized, SIMHarbor asks for it first. It then asks for installation confirmation, displays the server and selected card, and downloads to that card through its existing LPA and CommCenter transport. The profile remains disabled. Only the result is returned to the calling app; activation credentials are not placed in the launch URL or diagnostic messages.

The pairing key changes between builds. After installing or upgrading SIMHarbor, fully quit and reopen an app that was already running before using its install button; otherwise its old injected bridge cannot authenticate with the new SIMHarbor build.

The shared build key identifies a matching build, not the calling app: injected code or another local process that obtains the key can impersonate a peer. The confirmation screen must not be treated as proof of the requester's identity. The connection is not encrypted or individually authenticated after the handshake.

The request's optional EID must match the selected card. An optional server OID, including one in a manual activation code, is checked against the registered ID in the authentication certificate as required by [GSMA SGP.22](https://www.gsma.com/solutions-and-impact/technologies/esim/wp-content/uploads/2024/09/SGP.22-v2.6.pdf); the eUICC still authenticates the certificate and signature. The parser has been tested with generated certificates and an operator authentication certificate, not an actual OID-bearing download. Requests containing ICCID and non-null `CTCellularPlanProperties` are currently rejected because their semantics are not yet implemented. The bridge does not implement the system's plan-property storage, activation wizard, or automatic enabling. Support queries can return true even if SIMHarbor or a usable card is unavailable; an eventual installation can fail.

An incoming request waits up to 120 seconds for the app and card to become ready. If startup discovery finished before the card service connected, the app attempts one read-only refresh after the service authenticates. User confirmation must still be given within the separate request deadline.

Once a request has been sent, it is never automatically replayed. If the connection is lost, or profile loading fails without a recognized final card error, the native result is unknown because the card operation may have completed. A recognized final card error is returned as failure. Inspect the card before repeating an uncertain operation. The caller receives a background task while switching apps. If a result arrives in the background, the bridge holds its callback until the caller becomes active; if that process is terminated first, the callback cannot be delivered.

On one iOS 17.2.1 device, a carrier app's compatibility page changed after interception and real requests reached SIMHarbor and installed profiles. In one real install the native completion received success, but the app remained on its waiting screen. A 45-second simulated download reproduced the waiting screen; deferring completion until the calling app became active resolved it in the simulation. A later real installation also returned success, increased the card's profile count, and returned the carrier app to its order page without the waiting screen. A synthetic native request invoked inside an unrelated app also reached SIMHarbor and returned cancellation; this does not mean that app itself offers eSIM installation. These tests do not establish end-to-end compatibility for other apps or systems.
