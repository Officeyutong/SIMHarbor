# 实验性的原生安装桥接

[English](NATIVE_INSTALL.md) | **简体中文**

桥接在注入的应用进程内拦截 Core Telephony 方法，响应 eSIM 支持查询，并将 `addPlanWith:completionHandler:` 请求转交 SIMHarbor；这不是向系统注册第三方 LPA。越狱环境必须允许向发起应用注入。使用其他能力查询或安装接口的应用未必会经过该桥接。

调用进程打开 SIMHarbor，通过独立的已认证本机连接发送请求。如果尚未授权联网，SIMHarbor 会先请求联网授权；随后显示服务器和所选卡片，请用户确认，再通过现有 LPA 和 CommCenter 通信下载到该卡。新配置保持停用。返回给调用方的只有结果，启动 URL 和诊断消息不包含激活凭据。

配对密钥每次构建都会变化。安装或升级 SIMHarbor 后，如调用方此前已经运行，请先彻底关闭并重新打开它，再使用其安装按钮；否则旧进程内的桥接无法与新构建认证。

共享构建密钥只表示构建相匹配，不能识别调用应用：注入的代码或取得密钥的本机进程可以冒充通信对端。确认界面不能作为请求者身份的证明。握手之后的连接不加密，也没有逐条认证。

请求中若指定 EID，必须与所选卡片一致。可选服务器 OID（包括手动激活码中的 OID）会按 [GSMA SGP.22](https://www.gsma.com/solutions-and-impact/technologies/esim/wp-content/uploads/2024/09/SGP.22-v2.6.pdf) 与认证证书中的 registeredID 比较；eUICC 仍须认证证书及签名。解析器已用生成的证书和运营商认证证书测试，尚未使用含 OID 的真实下载测试。目前含 ICCID 的请求和非空 `CTCellularPlanProperties` 会被拒绝，因为相应语义尚未实现。桥接不实现系统的套餐属性存储、激活向导或自动启用。即使 SIMHarbor 或可用卡片不存在，支持查询也可能返回真，实际安装仍可能失败。

收到请求后，桥接最多等待 120 秒让 App 和卡片就绪。如果启动时的读取先于卡片服务连接而失败，服务认证后会尝试一次只读刷新。用户仍须在单独的请求期限内确认。

请求发出后不会自动重放。连接中断，或配置加载失败但没有可识别的卡片最终错误时，原生返回值为未知，因为卡片操作可能已经完成；有可识别的卡片最终错误时返回失败。对于结果不确定的操作，再次执行前应先读取卡片。切换应用时桥接会申请后台任务。如果结果在调用方处于后台时到达，桥接会等调用方重新活跃后再交付回调；若进程在此之前被终止，回调无法送达。

在一台 iOS 17.2.1 设备上，拦截后某运营商应用的兼容性页面发生变化，真实请求到达 SIMHarbor 并写入了配置。一次真实安装中观察到原生回调收到成功，但应用仍停在等待页面。45 秒模拟下载复现了等待界面；将回调推迟到调用方重新活跃后，同样的模拟测试回到订单页面。后续真实安装也返回成功、增加了卡片配置数量，调用方回到订单页面且没有卡住。在另一款无关应用的进程中主动调用原生接口，也成功到达 SIMHarbor 并返回取消结果；这不代表该应用本身提供 eSIM 安装功能。这些测试不能证明其他应用或系统的端到端兼容性。
