# 日志与自定义信令

## 英文原始日志

日志采用 UTC 时间，记录本 App 的操作阶段、APDU TX/RX、SW、HTTP 方法/URL/应用层请求与响应头、状态码、body 分块十六进制及传输错误。

- `TX` 是发送尝试；`RX` 是回读。超时不能证明卡端没有执行命令。
- `HEX` 后是实际字节。通过同一消息 ID 和 `offset` 可重组 body；`length` 是总字节数。
- `SW=9000` 表示 APDU 成功状态，但具体 ES10 操作结果仍需解析响应内容。
- 这是 App 可见的应用层信令，不是全机流量、TLS 加密记录或基带内部 QMI 抓包。
- 日志仅在内存保留约 4 MiB，超限淘汰旧记录并显示数量。导出才创建 `.log` 文件。
- 原始 HTTP/APDU 可能含激活凭据、证书、加密包和卡片标识。

## 原始 APDU 模式

每行一条短 APDU，最多 64 条。使用十六进制字节和空白；`#` 开头的行是注释。长度为 4–261 字节，Lc 和可选 Le 必须一致，不支持扩展长度 APDU。

输入基本通道 CLA，例如 `00` 或 `80`。App 会绑定实际分配的逻辑通道，支持通道 0–19 的 CLA 编码。

该模式显示原始响应，不自动处理 `61xx` 或 `6Cxx`。默认遇到非 `9000` 状态停止批次；关闭该开关后可以自行编排 GET RESPONSE 等命令。没有自动重发。

只读 Get EID 示例（按钮只填入，不自动发送）：

```text
80 E2 91 00 06 BF 3E 03 5C 01 5A
```

## ES10 DER 模式

输入一个完整 DER TLV。App 使用现有 libeuicc 发送 STORE DATA 分块，并收集 `61xx` 的后续响应。控制台显示拼接的响应正文；每条 APDU 和 SW 都在日志中。

- 使用配置的 MSS，默认 120。
- 最多 256 个请求块、4096 次传输、1 MiB 响应。
- 当前库的此模式只允许通道 0–3。
- 不提供自定义 HTTP 请求。

同一个 Get EID 请求的 DER：

```text
BF 3E 03 5C 01 5A
```

## 发送与结束

核对输入后点击发送并确认。请求共用串行队列，结束时关闭通道；错误后会显示已取得的响应。自定义命令可能改变或删除卡片，不会因为出现在文章中而自动执行。

1.2.1 已在真机验证上述两种只读 Get EID：原始 APDU 先返回 6115，关闭停止开关后以同一批次发送请求与 GET RESPONSE，最终返回 9000；DER 模式自动拼接相同的 EID 正文。未用自定义信令执行修改卡片的命令。
